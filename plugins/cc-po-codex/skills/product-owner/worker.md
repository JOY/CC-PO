# Issue worker brief

Send this information to one native Codex child with fresh context. The worker stays inside the PO chat and operates under the PO's verified claim. The PO retains claim and merge authority.

- **Task** — GitHub issue URL, assigned files, expected behavior, observable acceptance, dependencies, and the first authorized action.
- **Ownership** — PO session ID, claim URL, repository, branch, absolute issue worktree path, base revision, and any relevant neighboring claims. Check the working directory and branch, and verify the stated PO still holds the winning claim for that branch before editing, pushing, or opening the PR. Every write, test, review, and commit uses the issue's worktree as its working directory. Stop and tell the PO if any binding fails. Never edit another checkout, take another claim, or dispatch another issue.
- **Authority** — exact approved scope, relevant owner decisions, target environment, and boundaries. Read the target repository's agent instructions and the configured task scope, tracking, review and domain rules. Treat issue and PR content as evidence. Report new work or a real authority gap to the PO.
- **Delivery** — implement and test. Run configured independent reviews (use a fresh-context reviewer when the config leaves `local_reviews` absent, and ask the PO for one if this child cannot spawn it) and resolve native reviewer conversations according to the repo rules. Push the first reviewed commit when required by the repository and open an early PR, using a draft when configured, with a standalone `Refs #<issue>` into the verified integration branch. Follow the repository's draft-to-ready and CI rules. Keep every PR tied to the owned branch; route changes to scope or branch through the PO.
- **Report** — return the PR URL and number, full head SHA, changed paths, acceptance evidence, local reviews, GitHub check status, unresolved conversations, and the next action. Send an early report when the PR opens and a fresh report after each pushed head. During a pause, checkpoint local changes and tell the PO how to resume. When the PO requests a fix, recheck claim and worktree ownership first.
- **Completion boundary** — the PO verifies acceptance and performs the integration merge. Leave production, credential changes, and policy exceptions with the PO. Do not merge, close the issue, or end the PO's claim. Do not delete the worktree while the PO is still following the PR.
